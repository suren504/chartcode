# 过去 10 场攻防效率图

以下流程适用于本目录的生图任务。先进入本目录，再运行对应脚本。

## 确认运行环境

- **Windows 使用 Python。** 先运行 `py --version` 确认 Python 可用，再用 `py -m pip show Pillow` 检查该环境中的 Pillow。缺少依赖或版本低于 `requirements.txt` 的要求时，运行 `py -m pip install -r requirements.txt`，并使用同一个解释器生图。只有 `python` 命令可用时，先用 `python --version` 确认它指向 Python 3，再用它执行上述命令。
- **macOS 优先使用 Swift。** 先运行 `swift --version` 确认工具链可用。若提示缺少开发工具，按实际环境补齐 Xcode Command Line Tools。Swift 暂时无法运行时，可使用 `python3` 执行 Python 版，同样先检查环境和依赖。

## 首次运行

首次出图若为提供数据，则使用 `过去10场攻防效率数据.json`。直接运行下列对应命令，由脚本读取自带数据和示例日期。

| 环境 | 首次运行命令 |
| --- | --- |
| Windows | `py 生图.py` |
| macOS | `swift 生图.swift` |
| macOS 使用 Python 时 | `python3 生图.py` |

后续出图可在脚本名后传入 `YYYY-MM-DD` 使用目录内数据并指定日期，或传入 `数据.json YYYY-MM-DD` 使用另一份数据。

## 保留模板与处理错误

- 直接使用现有生图脚本和目录结构。保留原始模板的布局、文案、尺寸、排名标注规则和素材路径。只有用户明确要求调整模板，或定位到阻止出图的脚本错误时，才做必要的局部修改。禁止擅自重构。
- 运行失败时，先读完整报错，定位到环境、依赖、字体、路径、输入数据或脚本问题。自行修复可处理的问题，再用原命令重试。遇到确实需要用户提供信息或授权的情况，说明具体阻塞项。

## 核对与交付

- 确认命令成功，并核对本次生成的 PNG 可读且为 `2000 × 2500`。
- 成品写入本目录。Swift 输出 `过去10场攻防效率_YYYY-MM-DD.png`，Python 输出 `过去10场攻防效率_YYYY-MM-DD_Python.png`。
- 完成后向用户提供本次实际生成文件的绝对路径或可点击链接。
